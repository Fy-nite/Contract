# `ccl bindgen` — binding facades from a .NET assembly

Generate Contract-facing bindings for a real .NET assembly, so scripts and
the editor can use its types without hand-writing facades:

```bash
ccl bindgen V12.dll -o facades/                       # one .ct per namespace
ccl bindgen V12.dll --coi v12.coi --bind V12.Bindings.dll # + installable .coi
```

This solves the "how do I get compile + editor support for this DLL's types"
problem at the source level: one command reflects the assembly and emits
everything needed for Contract to see it.

## Usage

```text
ccl bindgen <assembly.dll> [-o outDir] [--coi name.coi] [--bind dll...] [--emit-path <value>]
```

| Option | Description |
|---|---|
| `-o`, `--output <dir>` | Output directory for the generated files (default: current directory). One `.ct` file per namespace is written here — keep them together, each file imports its siblings. |
| `--coi <path>` | Additionally compile every facade file to a `.orbt` module and pack them with the assembly into an installable `.coi` package. |
| `--bind <dll>` | A `[ClassBinding]` host assembly whose binding names are reserved — types that would collide with a bound facade are skipped. Repeatable. Also ships in the `--coi` archive. |
| `--emit-path <value>` | Override the `Path:` value emitted in each `<ClrImport>` attribute (default: the assembly's file name, valid when the generated files sit next to the assembly). Use a relative path when the files will live elsewhere, e.g. `--emit-path ../bindings/V12.dll`. |

## What it emits

One `.ct` file **per namespace** — Contract's import resolver maps a
namespace to a file by its *first* `namespace` declaration, so a
multi-namespace file would only ever register under one name. Each file
declares its namespace first, then imports its siblings so cross-namespace
type references resolve within a single compile:

```ct
// <auto-generated> Contract binding facades for V12 — namespace V12.Core
// Generated by `ccl bindgen`. Keep the generated files together in one
// directory: each file imports its siblings so cross-namespace type
// references resolve within a single compile.
namespace V12.Core;

import "V12.Components.ct";
import "V12.Core.Interfaces.ct";
import "V12.UI.ct";
// ... every other facade file ...

<ClrImport(Type: "V12.Core.GameRoot", Path: "V12.dll")>
Contract GameRoot {
    PersistentWorld: object;
    fn SelectWorld(world: object) { }
    static fn Log() { }
}
```

- **File names mirror namespaces** — `V12.Core` → `V12.Core.ct`; contracts
  in the global namespace land in `<AssemblyName>.Global.ct`.
- **Names are sanitized** — a CLR member or parameter whose name collides
  with a lexer keyword (`host`, `type`, `match`, ...) is emitted with a
  trailing underscore (`host_`), so the generated source always parses.
- **Bindings own their names** — `--bind` assemblies contribute their
  `[ClassBinding]` module names (and type names) as reserved: a real CLR type
  whose full name equals a bound facade name is skipped, exactly like
  assembly-link's reservation rules (see [ASSEMBLY_LINK.md](ASSEMBLY_LINK.md)).
- **Same surface as assembly-link** — the synthesis reuses
  `ClrReferenceLoader`, the assembly-link pre-pass, so the emitted facade set
  matches what `<AssemblyRef>`/`--link` would expose (v1 limits apply: public
  top-level non-generic types, no indexers/generic methods, overloads by
  arity).

## Using the generated `.ct` files

Copy the whole output directory into a project (next to the assembly, or
point `--emit-path` at wherever the DLL lives). The analyzer resolves each
`<ClrImport>` via reflection against `Path:`, so the language server gives
diagnostics, completion, and hover for every facade — the LSP runs the
analyzer, which is the piece that honors `ClrImport`+`Path`. Source-level
`import V12.Core;` also resolves: each file's first `namespace` declaration
registers it for namespace imports. Keep the files together — each imports
its siblings.

For runtime, the same mechanisms that back assembly-link apply: `ccl run`
reads the facades' metadata, and a host can register the assembly explicitly
(`ContractV12Host`-style hosts do this for their linked assemblies).

## `--coi` mode: ship facades as a package

```bash
ccl bindgen V12.dll --coi v12.coi --bind V12.Bindings.dll
ccl install v12.coi
```

`--coi` compiles every facade file to a `.orbt` module (as a library — no
`Main` required) and packs the modules with the target assembly (plus every
`--bind` assembly) into a `.coi`:

```
v12.coi
├── manifest.json
├── lib/
│   ├── V12.orbt                       # namespace V12
│   ├── V12.Core.orbt                  # namespace V12.Core
│   ├── V12.Core.Interfaces.orbt       # namespace V12.Core.Interfaces
│   └── ...
└── bindings/
    ├── V12.dll
    └── V12.Bindings.dll
```

The manifest `namespaces` map covers **every declared namespace plus its
ancestor prefixes**, aggregating descendant modules — so `import V12.Core;`
loads the whole `V12.Core.*` subtree and `import V12;` loads everything
(Java `import pkg.*`-style, the same convention as the packaged stdlib).

After `ccl install`, the compiler, runtime, and language server all pick the
package up automatically (namespace imports, binding registration — see
[COI_FORMAT.md](COI_FORMAT.md)), so consumers `import V12.Core;` with no
`--bind`.

## Bindings-only packages

`ccl pack` accepts packages with no modules when `--bind` assemblies are
given — useful when you only need the binding assemblies auto-registered
(no compiled module to import):

```bash
ccl pack MyBindings --bind path/to/MyBindings.dll -o mybindings.coi
```

## Relationship to the neighbours

| Tool | What it produces | When to use |
|---|---|---|
| `ccl bindgen` (this) | `.ct` facade source and/or a `.coi` with a facade module | Editor + compile support for a .NET assembly's types |
| `<AssemblyRef>` / `--link` | Runtime assembly-link, no artifacts | A single script that should call CLR types directly |
| `<ClrImport>` hand-written | One facade, authored manually | A single type you want full control over |
| `[ClassBinding]` + `--bind` | Host-defined module surface | Engine/script host APIs exposed under custom names |

## Limits (v1)

Same as assembly-link: public top-level non-generic types only (nested types
and open generic definitions are skipped; references to open generics and
delegates map to `object`), no indexers or generic methods, overloads matched
by arity. Facades carry no constructors in the emitted source (methods and
fields only); `new` on a facade type is a v1 limitation — call static/instance
methods and use fields/properties instead.
